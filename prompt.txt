## 1. Executive Summary & Business Context
We are building a white-label, multi-tenant B2B SaaS platform that enables small business owners to execute a **3-Way Warm AI Call Handoff**. 

### The Core Use Case:
1. A customer calls the business phone line.
2. The business owner directly answers the phone on their personal mobile/device.
3. Automatically (or via owner trigger), an AI Voice Agent joins the call as a 3rd party in a conference room.
4. The owner introduces the AI agent to the caller and politely hands over the call.
5. The owner hangs up, while the AI Agent stays on the line with the customer.
6. The AI Agent collects required intake details (name, budget, requirements, urgency, etc.).
7. Once the call ends, the backend extracts structured JSON data, logs the call recording and transcript, generates a summary report, and updates the customer database.

---

## 2. Current State vs. Target State

### What We Have Built Already (Proven Working Prototype)
We have successfully built and validated this entire call cycle using a No-Code setup:
- **Telephony & Routing:** Twilio (handling phone numbers & conference rooms)
- **Workflow Automation:** Make.com (handling webhooks, routing, and trigger execution)
- **AI Voice Agent:** Vapi.ai (handling speech-to-text, LLM reasoning, and text-to-speech)

This no-code pipeline works cleanly.

### What We Are Building Now (The Code-Based POC)
We want to transition away from Make.com into a custom, scalable, code-based SaaS architecture. 

**Key Goals for this Phase:**
1. Replicate the exact working Twilio + Vapi flow using direct API endpoints and Node.js code (eliminating Make.com).
2. Design a **Provider-Agnostic Abstraction Layer** so that in the future we can seamlessly plug in alternative Telephony providers (e.g., Plivo, SignalWire) and alternative Voice AI providers (e.g., Bolna, Retell AI) without rewriting our core platform logic.

---

## 3. What NOT to Build (Strict Boundaries)
- **Do NOT build custom telephony infrastructure:** We are NOT building our own telecom server; we are wrapping APIs like Twilio/Plivo.
- **Do NOT build automation platforms:** We are NOT building a generic workflow builder like Make.com; we are writing direct programmatic API handlers.
- **Do NOT build voice AI engines:** We are NOT training custom speech models; we are using APIs like Vapi/Bolna.

## 6. Definition of Done for this POC
The POC will be considered successful when:
1. An incoming call to a provisioned Twilio number triggers the Node.js backend.
2. The backend creates a Twilio Conference, dials the owner, and uses the Vapi API to add the AI agent to the room.
3. The owner can speak, hand off to the AI, and disconnect without dropping the customer.
4.The AI Agent finishes the intake, hangs up, and fires a webhook to the Node.js backend.
5.The backend saves the transcript, audio recording URL, and extracted JSON fields into the database.
6.The Tenant can log into the /dashboard and view the completed call record and summary, while the Super Admin (admin@admin.com) can see platform-wide telemetry.
